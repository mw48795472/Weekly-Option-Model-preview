> **2026-10-12 후속 실행 결과:** [TAIFEX 실제 호출·20거래일 분석·티커 검증](../../../taifex-analysis.md)을 추가했습니다. 이 문서의 호출 실패는 최초 조사 시점의 기록입니다.


확인 기준일: 2026-10-12 KST. 이 노트는 공식 웹페이지에서 확인한 사실과 실제 API 실행 검증을 구분한다. 추가 네트워크 조사 없이 확보 근거를 정리했으며 Git 저장소를 변경하거나 PR을 만들지 않았다.

## 1. 개별주식 위클리옵션은 무엇이며 어떤 종목이 대상인가?

### Takeaway
공식 현행 대상 명부는 전체 주식옵션 대상 32개 중 주간만기 대상 7개를 표시한다. 이 7개는 모두 상장 보통주이며 ETF 위클리 대상은 명부에서 확인되지 않았다. 이 명부는 대상 자격 목록이고 특정 날짜의 모든 행사가·만기·콜풋 실제 상장 시리즈 목록은 아니다.

### Cited Findings
- 명부 하단 효력일은 2026-09-03이며 주식옵션 대상 수는 32, 주간만기 대상 수는 7이다. 별도 열인 「是否為股票選擇權週契約標的」를 기준으로 구분했다. [TAIFEX 대상 명부](https://www.taifex.com.tw/cht/2/stockLists)
- 주간만기 대상은 CA 南亞(1303), CC 聯電(2303), CD 台積電(2330), CZ 長榮(2603), DH 鴻海(2317), DV 聯發科(2454), DX 緯創(3231)이다. 이 표의 원본 상품코드는 CA처럼 두 글자이며, 별도 옵션 API의 CAO 등 세 글자 표기는 이번 실제 응답으로 검증하지 못했다. [TAIFEX 대상 명부](https://www.taifex.com.tw/cht/2/stockLists)
- 주식 계약단위는 2,000주이며 계약조정 예외가 있다. 규격상 ETF는 원칙적으로 10,000 수익증권 단위이나 이 규격 자체가 ETF 위클리의 실제 상장을 뜻하지 않는다. 유럽형이며 만기 자동행사 대상 내재가치 포지션은 현금결제한다. [계약규격](https://www.taifex.com.tw/cht/2/sSO)
- 주간계약은 수요일에 상장해 두 번째 다음 수요일을 최종거래일로 삼을 수 있고, 월물과 같은 최종거래일인 주간계약은 상장하지 않는다. 월물은 해당 월 세 번째 수요일 만기다. 일반 거래시간은 현지 08:45~13:45, 만기계약의 최종거래일은 13:30 종료다. 최종결제가는 만기일 기초증권시장 마감 전 60분 산술평균을 사용한다. 휴일 등의 예외는 실제 거래일 캘린더를 적용해야 한다. [계약규격](https://www.taifex.com.tw/cht/2/sSO)
- 명부의 17:25~익일05:00 열은 명확히 「盤後交易時段 交易時間(期貨契約)」, 즉 선물계약 야간시간이다. 이를 주식옵션 야간거래시간으로 가져오면 안 된다. [명부 열 제목](https://www.taifex.com.tw/cht/2/stockLists)

### Inferences
- 실제 계약 마스터의 기본키는 거래소·상품코드·만기/주차·행사가·콜풋·조정계약 식별자를 합쳐 설계해야 한다. 기초주식 코드 2330만으로는 TSMC의 여러 옵션계약을 구분할 수 없다.
- 7개 자격 대상에 매일 동일 개수의 행사가가 상장되거나 거래가 발생한다고 가정하지 않는다. 실제 DailyMarketReportOpt 또는 공식 계약/최종결제 내역으로 대상자격과 관측된 시리즈를 구분해야 한다.
- 월물과 주간만기 분리는 실제 최종거래일과 주차 식별자를 함께 사용해야 한다. 상품명에만 weekly 태그를 붙이면 월물을 잘못 포함할 수 있다.

### Gaps
- 이번 실행에서는 CAO/CCO/CDO/CZO/DHO/DVO/DXO 코드, 202610W1 등 실제 응답의 주차값 및 행사가별 계약 수를 확인하지 못했다. 상기 두 글자 명부코드에서 API 코드를 기계적으로 합성해 검증완료로 보고하지 않았다.
- 공식 최종결제가 페이지는 열었지만 이번 도구 출력에서 개별 데이터 행을 확보하지 못했다. [주식옵션 최종결제가](https://www.taifex.com.tw/cht/5/sSOFSP)
- TXO 지수옵션의 수요일/금요일 위클리 규격과 코드 체계는 이 노트에서 검증하지 못했다. 개별주식 수요일 규칙을 금요일 지수옵션에 일반화하지 않는다.

## 2. OpenAPI 구조와 실제 응답 검증 상태는?

### Takeaway
공식 OpenAPI 진입점이 Swagger UI인 것은 확인했다. 그러나 이 실행에서 swagger.json 원문 및 데이터 JSON을 획득하지 못했으므로 인증방식, 서버 base URL, 요청 파라미터, 응답 필드 및 최신 스냅샷 범위를 검증완료로 표현할 수 없다.

### Cited Findings
- 공개 포털 진입점은 Swagger UI로 응답했으며 웹 텍스트 추출 결과는 빈 화면이었다. [TAIFEX OpenAPI](https://openapi.taifex.com.tw/)
- 다음은 사용자 요청에 포함된 조사대상 API 이름이며, 이번 실행으로 명세·응답을 재확인한 목록은 아니다: DailyMarketReportOpt, DailyOptionsDelta, PutCallRatio, OpenInterestOfLargeTradersOptions, OptionsTimeAndSalesData. SSOLists, ContractAdj 및 최종결제 관련 API도 확인대상이다. 공식 진입점: [OpenAPI](https://openapi.taifex.com.tw/)

|조사대상|기대 연구용도|이번 확인 상태|
|---|---|---|
|DailyMarketReportOpt|옵션 계약·만기/주차·행사가·콜풋별 일별 시장자료|엔드포인트/필드/조회범위 실제 검증 미완료|
|DailyOptionsDelta|계약별 델타 참조값|계산기준·시점·필드 미확인|
|PutCallRatio|시장 집계 풋콜지표|집계범위·거래량/OI 구분 미확인|
|OpenInterestOfLargeTradersOptions|대규모 거래자 포지션 집계|개별투자자 보유내역으로 해석 금지; 범위 미확인|
|OptionsTimeAndSalesData|체결 틱|대량 다운로드 수행하지 않음; 기간·필드 미확인|
|SSOLists|주식옵션 상품/기초자산 매핑 후보|공식 HTML 대상 명부만 확인; JSON 미확인|
|ContractAdj|기업행사 계약조정|JSON 구조·유효일 및 연결키 미확인|
|최종결제 관련 자료|실제 만기·결제가격 및 상품코드 검증|웹페이지 존재 확인; 데이터 행 미확보|

### Inferences
- 일별 JSON을 받더라도 날짜 필터 지원이 없으면 과거 조회 API로 사용할 수 없다. 반드시 swagger parameters와 실제 Date 값 범위를 확인한 뒤 스냅샷 저장 수집기인지 역사 조회기인지 결정해야 한다.
- ContractDate / ContractMonth(Week)처럼 이름이 비슷한 필드를 별도 의미 확인 없이 통합하지 않는다. 만기주차·주월물·세션·콜풋·행사가를 원형 보존한 뒤 정규화한다.
- OI는 가격 관측시각과 공표시각을 분리해 적재해야 한다. 무거래 가격의 '-'·빈 문자열·0 의미를 명세로 확인하기 전 0가격으로 대체하지 않는다. 정산가와 실거래 종가를 별도 필드로 둔다.

### Gaps
- node fetch로 https://openapi.taifex.com.tw/swagger.json 호출을 시도했으나 fetch failed로 종료됐다. 이어서 승인된 외부 shell 다운로드를 요청했으나 장시간 대기 후 사용자/상위 에이전트 중단으로 완료되지 않았다. 저장된 swagger 파일은 ENOENT로 존재하지 않음을 확인했다.
- 따라서 HTTP 성공상태, 응답 행수, 응답 기준일·날짜 범위, 인증키 필요 여부, rate limit, request parameters, 보안 정의를 검증하지 못했다. 무인증 GET 성공으로 보고하지 않는다.
- 임의로 ?date=, ?startDate=, ?endDate= 등을 붙인 예시는 제공하지 않는다.
- 실제 JSON 샘플은 없으며 예상 필드로 가공한 가짜 샘플 CSV를 만들지 않았다.

## 3. 장기 역사·분봉·호가를 어떻게 확보해야 하나?

### Takeaway
TAIFEX는 옵션 역사 다운로드 공식 페이지를 제공한다. 이 페이지 존재는 확인했지만 30일 제한·연간 ZIP·최초 제공일·유료 장기상품의 현재 조건은 이번 실행에서 확인되지 않았다. 이를 무료 OpenAPI 역사보장으로 표현하면 안 된다.

### Cited Findings
- 공식 영어 사이트에 Options Historical Data Download 페이지가 있다. [옵션 역사자료 다운로드](https://www.taifex.com.tw/enl/eng3/optDailyMarketView?menuid1=03)
- 계약별 최종결제가격을 위한 별도 주식옵션 페이지가 있다. [주식옵션 최종결제가](https://www.taifex.com.tw/cht/5/sSOFSP)

### Inferences
- 조달 문의는 최근/현재 JSON, 일별 역사 파일, 체결 틱, 호가 이력을 나눠 한다. 체결자료만으로 bid/ask 스프레드나 주문장 복원이 가능하다고 보지 않는다.
- 연구 우선순위는 일별 옵션 가격·OI + 실제 계약 캘린더 + 기초주식 가격·기업행사다. 기초현물은 TWSE/TPEx의 별도 데이터 권한과 시계열이 필요하며 옵션 API 하나가 현물의 모든 분봉을 제공한다고 가정하지 않는다.
- H2 전이는 지수옵션과 개별주식옵션을 분리해 데이터 패널을 구성해야 한다. H5/H6에는 실제 만기·일별 OI가, REV에는 동기화된 기초자산 장중 가격이, H9b에는 호가·잔량 이력이 추가로 필요하다.

### Gaps
- 30일/연간 다운로드, eDatashop 주문 단위와 비용, 최초 제공일, 과거 계약조정 마스터 보존 여부, 장중 호가 이력 이용조건은 공급처에 확인 필요하다.
- 주식 위클리의 최초 도입일 및 7개 대상의 개별 편입일은 검증하지 못했다. 현행 대상 목록을 과거 전체기간의 동일 모집단으로 소급하지 않는다.
- 공개 대시보드·원시자료 재배포 허용 여부는 데이터 상품별 이용조건을 확인해야 한다.
